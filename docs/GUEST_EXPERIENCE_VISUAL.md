## Mobile vs Web Experience

### 📱 Mobile Experience (both work)

#### Option A: Mobile App
```
Native App:
apps/mobile/

User Flow:
1. Download PartyHause app
2. Sign in with email
3. See invitation in Events tab
4. Tap to open event details
5. Native QR code viewer
6. Push notifications
7. Add to calendar
```

#### Option B: Web PWA
```
Web Browser:
www.partyhause.com/guest/{id}

User Flow:
1. Click email link
2. Opens in mobile browser
3. Add to Home Screen
4. Acts like native app
5. QR code in browser
6. Works offline
```

### 💻 Desktop Experience

```
Web Browser:
www.partyhause.com/guest/{id}

Large Screen View:
┌────────────────────────────────────────┐
│  [Event Details]    [QR Code]          │
│  Side by side       Always visible     │
│  layout             Printable          │
└────────────────────────────────────────┘
```

## Technical Notes

### File Locations:
```
Web Guest View:
├─ src/components/GuestView.tsx          (Main component)
├─ src/store/usePartyStore.ts            (State management)
└─ src/lib/supabase.ts                   (Data fetching)

Email Templates:
├─ apps/mobile/lib/email.ts              (buildInvitationEmail)
└─ api/send-email.ts                     (MailerSend integration)

Host Guest Management:
├─ apps/mobile/app/events/[id]/guests.tsx (Mobile)
├─ src/components/GuestListWithCrew.tsx   (Web)
└─ api/guests.ts                          (API endpoints)

Check-in System:
├─ apps/mobile/components/QRScanner.tsx   (Mobile scanner)
└─ api/guests.ts → POST /check-in         (Backend)
```

### Database Schema:
```sql
Table: guests
├─ id (uuid)
├─ event_id (uuid) → references events(id)
├─ name (text)
├─ email (text)
├─ phone (text, optional)
├─ rsvp_status (enum: pending|accepted|declined|maybe)
├─ rsvp_responded_at (timestamp)
├─ plus_ones (integer)
├─ plus_ones_names (text[])
├─ dietary_restrictions (text)
├─ notes (text)
├─ checked_in (boolean)
├─ checked_in_at (timestamp)
├─ invited_at (timestamp)
├─ email_sent (boolean)
├─ email_opened (boolean)
├─ email_clicked (boolean)
├─ created_at (timestamp)
└─ updated_at (timestamp)
```

## Testing the Flow

### Manual Test Script:

```bash
# 1. Create test event and guest
curl -X POST https://www.partyhause.com/api/events \
  -H "Authorization: Bearer {token}" \
  -d '{"name":"Test Party","date":"2025-12-01T20:00:00Z"}'

# 2. Add test guest
curl -X POST https://www.partyhause.com/api/guests \
  -H "Authorization: Bearer {token}" \
  -d '{"event_id":"{event_id}","name":"John Doe","email":"john@example.com"}'

# 3. Get guest invitation link
# URL format: https://www.partyhause.com/guest/{guest_id}

# 4. Open link in browser
# Should see GuestView with event details

# 5. Click "Show My QR Code"
# Should display QR code with guest ID

# 6. Test check-in
curl -X POST https://www.partyhause.com/api/guests/check-in \
  -H "Authorization: Bearer {token}" \
  -d '{"guest_id":"{guest_id}"}'
```
