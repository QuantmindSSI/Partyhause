## 📱 Mobile Experience Innovation

### Gesture-Based Event Discovery

**The Problem:**
Traditional event management apps use boring lists or static grids that don't engage users or convey the excitement of upcoming events.

**Our Solution:**
A **Netflix-inspired swipeable carousel** with physics-based animations that makes browsing events feel like an experience, not a chore.

**Technical Highlights:**

**1. 3D Card Transforms:**
```typescript
// Each card rotates and scales based on position
// Creating depth and focus on the center card
const rotation = interpolate(
  position,
  [-CARD_SPACING, 0, CARD_SPACING],
  [15, 0, -15]  // Degrees of rotation
);

const scale = interpolate(
  position,
  [-CARD_SPACING, 0, CARD_SPACING],
  [0.9, 1, 0.9]  // Scale factor
);
```

**2. Velocity-Based Physics:**
- Swipe velocity determines animation duration
- Fast swipes = quick snaps to next card
- Slow swipes = smooth, controlled movement
- Velocity decay for natural feel

**3. Infinite Scroll Loop:**
- Events loop seamlessly
- No "end" to the carousel
- Boundary detection with automatic repositioning
- Maintains performance with large event lists

**4. Smart Centering:**
- Cards automatically snap to center
- Accounts for screen size variations
- Works across all device sizes
- Maintains position after scroll/swipe

**5. Performance Optimizations:**
- 60fps animations with Reanimated
- Runs on UI thread (not JavaScript)
- Efficient re-renders with React.memo
- Lazy loading of off-screen cards

**User Benefits:**
- ✨ Engaging, fun way to browse events
- 🎯 Clear focus on one event at a time
- 👆 Natural touch interactions
- 🔄 Smooth, fluid animations
- 💫 Memorable first impression

### Gesture-Based Event Discovery

**The Problem:**
Traditional event management apps use boring lists or static grids that don't engage users or convey the excitement of upcoming events.

**Our Solution:**
A **Netflix-inspired swipeable carousel** with physics-based animations that makes browsing events feel like an experience, not a chore.

**Technical Highlights:**

**1. 3D Card Transforms:**
```typescript
// Each card rotates and scales based on position
// Creating depth and focus on the center card
const rotation = interpolate(
  position,
  [-CARD_SPACING, 0, CARD_SPACING],
  [15, 0, -15]  // Degrees of rotation
);

const scale = interpolate(
  position,
  [-CARD_SPACING, 0, CARD_SPACING],
  [0.9, 1, 0.9]  // Scale factor
);
```

**2. Velocity-Based Physics:**
- Swipe velocity determines animation duration
- Fast swipes = quick snaps to next card
- Slow swipes = smooth, controlled movement
- Velocity decay for natural feel

**3. Infinite Scroll Loop:**
- Events loop seamlessly
- No "end" to the carousel
- Boundary detection with automatic repositioning
- Maintains performance with large event lists

**4. Smart Centering:**
- Cards automatically snap to center
- Accounts for screen size variations
- Works across all device sizes
- Maintains position after scroll/swipe

**5. Performance Optimizations:**
- 60fps animations with Reanimated
- Runs on UI thread (not JavaScript)
- Efficient re-renders with React.memo
- Lazy loading of off-screen cards

**User Benefits:**
- ✨ Engaging, fun way to browse events
- 🎯 Clear focus on one event at a time
- 👆 Natural touch interactions

```typescript
// Each card rotates and scales based on position

const rotation = interpolate(
  position,
  [-CARD_SPACING, 0, CARD_SPACING],
  [15, 0, -15]  // Degrees of rotation

const scale = interpolate(
  position,
  [-CARD_SPACING, 0, CARD_SPACING],
  [0.9, 1, 0.9]  // Scale factor
);
```

- Maintains position after scroll/swipe

📘 Haus Co-Pilot: Comprehensive Technical Essence & Architecture Document

Version: 4.0 (Autonomous Agent Architecture)

Date: November 28, 2025

Status: Blueprint for Production

Core Concept: "The First Empirically-Driven AI Event Orchestrator"

1. Executive Summary

Haus Co-Pilot is a Multi-Agent System (MAS) that serves as an autonomous director for social events. Unlike traditional apps that offer static forms, Haus Co-Pilot actively senses the environment (social and physical), reasons about optimal outcomes, and executes logistics via API integrations.

The system is built on a Supervisor-Worker Topology using LangGraph, enabling a "Human-in-the-Loop" workflow where the AI proposes high-level strategies and executes low-level tasks upon approval.

2. High-Level Architecture: The "Agent Swarm"

The system follows a hub-and-spoke model. The user communicates only with the Supervisor, who maintains the "Event Truth" and routes commands to specialized agents.

2.1 The Connection Diagram

The Flow of Logic:

Input: User Message ("The party is too quiet") OR Sensor Trigger (Microphone detects <30dB).

Supervisor Node: Analyzes intent. Decides which expert is needed.

Routing: Passes state to the Ludologist (Game) Agent.

Execution: Ludologist calls Spotify API + Push Notification Tool.

Feedback: Ludologist reports back to Supervisor ("Music changed, game launched").

Output: Supervisor updates the UI Artifact.

3. The Agent Roster & Tooling Definition

Each agent is a specialized LLM instance (GPT-4o or Claude 3.5 Sonnet) equipped with specific Function Tools.

4. Data Architecture: The "Sensory Brain"

The uniqueness of Haus Co-Pilot lies in its tri-hybrid database structure.

4.1 The Tri-Hybrid Schema

Relational (PostgreSQL/Supabase):

Purpose: Transactional truth.

Data: Users, Auth, Payments, Event Details (Date, Time).

Graph (Neo4j or Recursive PG):

Purpose: Social Engineering.

Data:

(:User)-[:ATTENDED]->(:Event)

(:User)-[:KNOWS {strength: 0.8}]->(:User)

(:User)-[:HAS_INTEREST]->(:Topic)

Vector (pgvector / Pinecone):

Purpose: Semantic Memory & RAG.

Data:

Vendor Embeddings: "Rustic Italian catering near me."

Past Event Embeddings: "Remember the playlist from Sarah's party?"

6. Empirical Feature Implementation

How the "Unique Features" are technically wired.

6.1 The "Dead Air" Detection Loop

Sensor: Host App samples microphone amplitude (dB) every 30s.

Ingest: Sends metric to POST /events/:id/telemetry.

Analysis: Edge Function calculates rolling average.

Trigger: If avg_db < threshold AND time > start_time:

System injects a system prompt to Ludologist Agent: "Vibe is critical. Suggest intervention."

Action: Agent prompts Host: "It's quiet. Want to start the Trivia game?"

6.2 The "Guest List Optimizer"

Input: Host selects "Theme: Board Games."

Query: Wingman Agent queries the Graph DB.

Find: Users connected to Host.

Filter: Interest = 'Strategy Games'.

Exclude: Users with Flake_Score > 50%.

Output: Returns a ranked list of 10 recommended invites to the Supervisor.
